31. Relationships in DRF

Learn how to represent database relationships using Django models and DRF serializers.

1. What are Database Relationships?

Database Relationship mhanje don kiwa adhik database tables madhil connection.

Definition

Database relationships define how records in different tables are connected to each other.

Example

Samja College database madhye Student ani Department ase don tables aahet.

Student Table

id    name       department_id
1     Rohan      1
2     Amit       1
3     Rahul      2

Department Table

id    department_name
1     Computer Science
2     Mathematics

Ya example madhye department_id mule Student ani Department tables connect hotat.

2. Types of Database Relationships

Django madhye mainly three types of database relationships use kele jatat.

Relationship Meaning Django Field
One-to-One One record connects to one record. OneToOneField
One-to-Many One record connects to multiple records. ForeignKey
Many-to-Many Multiple records connect to multiple records. ManyToManyField

3. One-to-One Relationship

One-to-One relationship madhye eka record cha sambandh dusrya table madhil fakt eka record sobat asto.

Example

Ek Student cha ekach Profile asu shakto. Ek Profile fakt eka Student sobat connected asto.

Student Rohan
1 ───── 1
Profile Rohan's Profile

Django Model Example

File: api/models.py

from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)


class Profile(models.Model):
    student = models.OneToOneField(
        Student,
        on_delete=models.CASCADE,
        related_name='profile'
    )

    phone = models.CharField(max_length=15)
    address = models.CharField(max_length=200)

Explanation

  • OneToOneField don models madhye one-to-one connection create karte.
  • on_delete=models.CASCADE mule Student delete zalyas tyacha Profile suddha delete hoto.
  • related_name='profile' mule student.profile vaprun profile access karta yete.

4. One-to-Many Relationship

One-to-Many relationship madhye eka record sobat dusrya table madhil multiple records connected astat.

Example

Eka Department madhye multiple Students asu shaktat. Pan pratyek Student eka Department sobat connected asto.

Department Computer Science
1
|
+------ 1 Student
+------ 2 Student
+------ 3 Student
Multiple Students Rohan, Amit, Rahul

Django Model Example

from django.db import models

class Department(models.Model):
    name = models.CharField(max_length=100)


class Student(models.Model):
    name = models.CharField(max_length=100)

    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE,
        related_name='students'
    )

Explanation

  • ForeignKey one-to-many relationship create karte.
  • Student model madhye Department chi reference store hote.
  • related_name='students' mule department.students vaprun students access karta yetat.
  • on_delete=models.CASCADE mule Department delete zalyas related Students suddha delete hotat.

5. Many-to-Many Relationship

Many-to-Many relationship madhye eka table madhil multiple records dusrya table madhil multiple records sobat connected astat.

Example

Ek Student multiple Courses join karu shakto. Ani ek Course multiple Students join karu shaktat.

Student and Course

Rohan  -> Python, Django
Amit   -> Python, Java
Rahul  -> Django, Java

Django Model Example

from django.db import models

class Course(models.Model):
    name = models.CharField(max_length=100)


class Student(models.Model):
    name = models.CharField(max_length=100)

    courses = models.ManyToManyField(
        Course,
        related_name='students'
    )

Explanation

  • ManyToManyField many-to-many relationship create karte.
  • Ek Student multiple Courses select karu shakto.
  • Ek Course multiple Students sobat connect hou shakto.
  • Django automatically intermediate table create karte.

6. What are Nested Serializers?

Nested Serializer cha use related model cha data main serializer madhye display karanyasathi hoto.

Example

Student API response madhye Student sobat tyacha Department details suddha display karaycha aahe.

Step 1 – Create DepartmentSerializer

File: api/serializers.py

from rest_framework import serializers
from .models import Department, Student


class DepartmentSerializer(serializers.ModelSerializer):

    class Meta:
        model = Department
        fields = '__all__'

Step 2 – Create StudentSerializer

class StudentSerializer(serializers.ModelSerializer):

    department = DepartmentSerializer(read_only=True)

    class Meta:
        model = Student
        fields = ['id', 'name', 'department']

Example API Response

{
    "id": 1,
    "name": "Rohan",
    "department": {
        "id": 1,
        "name": "Computer Science"
    }
}

Nested Serializer mule department cha complete object Student API response madhye display hoto.

Important: read_only=True aslyamule ya nested field madhun Department create kiwa update karta yet nahi. Nested write sathi custom create() kiwa update() method implement karavi lagte.

7. PrimaryKeyRelatedField

PrimaryKeyRelatedField cha use related object tyachya primary key ID madhun represent karanyasathi hoto.

Example

class StudentSerializer(serializers.ModelSerializer):

    department = serializers.PrimaryKeyRelatedField(
        read_only=True
    )

    class Meta:
        model = Student
        fields = ['id', 'name', 'department']

API Response

{
    "id": 1,
    "name": "Rohan",
    "department": 1
}

Ya example madhye department cha complete object denyayevaji fakt department ID return hoto.

8. StringRelatedField

StringRelatedField cha use related object tyachya string representation madhye display karanyasathi hoto.

Step 1 – Add __str__() Method

File: api/models.py

class Department(models.Model):

    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name

Step 2 – Use StringRelatedField

File: api/serializers.py

class StudentSerializer(serializers.ModelSerializer):

    department = serializers.StringRelatedField()

    class Meta:
        model = Student
        fields = ['id', 'name', 'department']

API Response

{
    "id": 1,
    "name": "Rohan",
    "department": "Computer Science"
}

StringRelatedField related object cha __str__() method madhun milnari string display karte.

9. Relationship Fields Comparison

Field Output Use
Nested Serializer Complete object Related details display karne.
PrimaryKeyRelatedField Object ID Primary key display karne.
StringRelatedField String value Object chi readable value display karne.

10. Practical Student-Course API

Ata aapan Student ani Course madhye Many-to-Many relationship implement karuya.

Step 1 – Create Models

File: api/models.py

from django.db import models


class Course(models.Model):

    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name


class Student(models.Model):

    name = models.CharField(max_length=100)

    courses = models.ManyToManyField(
        Course,
        related_name='students',
        blank=True
    )

    def __str__(self):
        return self.name

Step 2 – Run Migrations

python manage.py makemigrations

python manage.py migrate

Step 3 – Create Serializers

File: api/serializers.py

from rest_framework import serializers
from .models import Student, Course


class CourseSerializer(serializers.ModelSerializer):

    class Meta:
        model = Course
        fields = '__all__'


class StudentSerializer(serializers.ModelSerializer):

    courses = CourseSerializer(
        many=True,
        read_only=True
    )

    class Meta:
        model = Student
        fields = ['id', 'name', 'courses']

Step 4 – Create ViewSets

File: api/views.py

from rest_framework.viewsets import ModelViewSet

from .models import Student, Course
from .serializers import (
    StudentSerializer,
    CourseSerializer
)


class StudentViewSet(ModelViewSet):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer


class CourseViewSet(ModelViewSet):

    queryset = Course.objects.all()
    serializer_class = CourseSerializer

Step 5 – Register Routers

File: api/urls.py

from rest_framework.routers import DefaultRouter

from .views import StudentViewSet, CourseViewSet

router = DefaultRouter()

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

router.register(
    'courses',
    CourseViewSet,
    basename='course'
)

urlpatterns = router.urls

Step 6 – Test API

GET /api/students/

GET /api/courses/

Example Student API Response

{
    "id": 1,
    "name": "Rohan",
    "courses": [
        {
            "id": 1,
            "name": "Python"
        },
        {
            "id": 2,
            "name": "Django"
        }
    ]
}
Important: Ya practical madhye courses read_only=True aahet. Mhanun Student API madhun courses add kiwa update hot nahit. Relationship create karanyasathi Django admin, shell kiwa separate writable serializer/API implement karavi lagel.

11. Important Points to Remember

  • Database relationships tables madhye connection create kartat.
  • OneToOneField one-to-one relationship sathi aahe.
  • ForeignKey one-to-many relationship sathi aahe.
  • ManyToManyField many-to-many relationship sathi aahe.
  • Nested Serializers related object details display kartat.
  • PrimaryKeyRelatedField related object chi ID display karte.
  • StringRelatedField related object chi string value display karte.
  • related_name reverse relationship access karanyasathi vapartat.
  • read_only=True mule field madhun write karta yet nahi.
  • Nested writes sathi custom create() kiwa update() methods lagu shaktat.

13. Interview Questions

Q1. What are Database Relationships?

Database relationships define connections between records in different database tables.

Q2. What is ForeignKey?

ForeignKey is used to create a one-to-many relationship between two models.

Q3. What is ManyToManyField?

ManyToManyField creates a relationship where multiple records can connect to multiple records.

Q4. What is a Nested Serializer?

A Nested Serializer displays related model data inside another serializer.

Q5. What is PrimaryKeyRelatedField?

It represents a related object using its primary key.

Q6. What is StringRelatedField?

It represents a related object using its string representation.

Q7. What is related_name?

related_name defines the name used to access related objects from the reverse side of a relationship.
