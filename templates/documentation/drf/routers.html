DJANGO REST FRAMEWORK

21. Routers in DRF

Learn how to automatically generate API URL patterns using Routers and ViewSets.

1. What are Routers?

Routers ya Django REST Framework madhil classes aahet. Tyanchya madatine ViewSets sathi URL patterns automatically generate hotat.

Definition

Routers are used to automatically generate URL patterns for registered ViewSets in Django REST Framework.

Why use Routers?

  • URLs automatically generate hotat.
  • Manual URL configuration kami hote.
  • CRUD API routing sope hote.
  • ViewSets sobat easily work kartat.
  • Code clean ani organized rahto.
Important: Routers he ViewSets sobat use kele jatat. Normal function-based views sathi Router chi garaj naste.

2. Types of Routers

DRF madhye don commonly used built-in routers aahet.

Router Purpose
SimpleRouter ViewSets sathi basic URL patterns generate karto.
DefaultRouter URL patterns sobat API root view pan provide karto.

3. SimpleRouter

SimpleRouter ha basic router aahe. To registered ViewSets sathi list ani detail URL patterns generate karto.

Definition

SimpleRouter automatically creates URL patterns for the list and detail actions of a ViewSet.

Import SimpleRouter

from rest_framework.routers import SimpleRouter

Example

from rest_framework.routers import SimpleRouter
from .views import StudentViewSet

router = SimpleRouter()

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

urlpatterns = router.urls

Generated URLs

/students/
/students/{pk}/

Ithe list URL var GET ani POST requests handle hotat. Detail URL var GET, PUT, PATCH ani DELETE requests handle hotat, jar ViewSet madhye te actions available astil.

4. DefaultRouter

DefaultRouter ha SimpleRouter sarkhach URL patterns generate karto. Tyashivay to API root view pan provide karto.

Definition

DefaultRouter automatically generates URL patterns for ViewSets and also provides an API root view.

Import DefaultRouter

from rest_framework.routers import DefaultRouter

Example

from rest_framework.routers import DefaultRouter
from .views import StudentViewSet

router = DefaultRouter()

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

urlpatterns = router.urls

Generated URLs

/                 → API Root
/students/        → Student List
/students/{pk}/   → Student Detail

DefaultRouter API root view provide karto. Tithe registered ViewSets che links disu shaktat.

5. register() Method

register() method cha use Router madhye ViewSet register karanyasathi hoto.

Definition

The register() method connects a URL prefix with a ViewSet.

Syntax

router.register(
    prefix,
    viewset,
    basename
)

Parameters

Parameter Meaning
prefix URL madhil starting path.
viewset Register karaycha ViewSet class.
basename Generated URL names sathi base name.

Example

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

Ya example madhye students ha URL prefix aahe ani student ha URL names sathi basename aahe.

6. What is basename?

basename cha use Router generate karat aslelya URL names madhye base name define karanyasathi hoto.

Definition

Basename is used to create URL names for registered ViewSet routes.

Example

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

Generated URL Names

student-list
student-detail
Important: ViewSet madhye queryset define nasel tar Router la basename manually provide karne avashyak aste.

7. How Router Generates URLs?

Router ViewSet madhil available actions nusar list ani detail routes generate karto.

HTTP Method URL Action
GET /students/ list
POST /students/ create
GET /students/1/ retrieve
PUT /students/1/ update
PATCH /students/1/ partial_update
DELETE /students/1/ destroy

He mapping ModelViewSet sarkhya CRUD actions available aslelya ViewSet sathi lagu hote.

8. Custom URLs with ViewSets

ViewSet madhye custom API endpoint create karanyasathi @action decorator use karta yeto.

Definition

The @action decorator is used to create custom actions in a ViewSet.

Example

from rest_framework.viewsets import ModelViewSet
from rest_framework.decorators import action
from rest_framework.response import Response

class StudentViewSet(ModelViewSet):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer

    @action(
        detail=False,
        methods=['get']
    )
    def active_students(self, request):

        students = self.get_queryset().filter(age__gte=18)

        serializer = self.get_serializer(
            students,
            many=True
        )

        return Response(serializer.data)

Custom API URL

GET /students/active_students/

Understanding detail Parameter

Value Meaning
detail=False Collection-level action. Specific object ID lagat nahi.
detail=True Single-object action. URL madhye object ID asto.

Custom Detail Action Example

@action(
    detail=True,
    methods=['get']
)
def student_info(self, request, pk=None):

    student = self.get_object()

    serializer = self.get_serializer(student)

    return Response(serializer.data)
GET /students/1/student_info/

9. Practical Student API using DefaultRouter

Ata aapan ModelViewSet ani DefaultRouter vaprun complete Student CRUD API create karuya.

Step 1 – Model

Existing Student model asel tar toch use kara. 

# api/models.py

from django.db import models

class Student(models.Model):

    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)
    age = models.PositiveIntegerField()

    def __str__(self):
        return self.name

Step 2 – Serializer

# api/serializers.py

from rest_framework import serializers
from .models import Student

class StudentSerializer(serializers.ModelSerializer):

    class Meta:
        model = Student
        fields = '__all__'

Step 3 – ViewSet

File: api/views.py

from rest_framework.viewsets import ModelViewSet

from .models import Student
from .serializers import StudentSerializer


class StudentViewSet(ModelViewSet):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer

Step 4 – Router

File: api/urls.py

from rest_framework.routers import DefaultRouter
from .views import StudentViewSet

router = DefaultRouter()

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

urlpatterns = router.urls

Step 5 – Main URLs

File: config/urls.py

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('api/', include('api.urls')),
]
Important: Existing Student model ani serializer already astil tar punha create karu naka. Same ViewSet sathi duplicate URL patterns add karu naka.

11. SimpleRouter vs DefaultRouter

SimpleRouter DefaultRouter
Basic URL patterns generate karto. URL patterns sobat API root provide karto.
Separate API root view nahi. API root view available aste.
Simple routing requirement sathi useful. API root pahije asel tar useful.

12. Important Points to Remember

  • Routers ViewSets sathi URL patterns generate kartat.
  • SimpleRouter basic routes create karto.
  • DefaultRouter API root view pan provide karto.
  • register() method ViewSet register karte.
  • prefix URL path define karto.
  • basename URL names generate karanyasathi use hoto.
  • @action decorator custom endpoints create karto.
  • detail=False collection-level action aahe.
  • detail=True single-object action aahe.
