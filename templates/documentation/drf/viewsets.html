20. ViewSets in DRF

Learn how to manage multiple API operations using ViewSets and Routers.

1. What are ViewSets?

ViewSets ya DRF madhil classes aahet. Tyanchya madatine multiple API operations ekach class madhye handle karta yetat.

Definition

ViewSets are classes in Django REST Framework that group related API operations into a single class.

Why use ViewSets?

  • Multiple API operations ekach class madhye handle hotat.
  • Code repetition kami hote.
  • URL routing sope hote.
  • Routers sobat automatically URLs generate karta yetat.
  • Code clean ani organized rahto.

ViewSets Working Flow

Client Request GET, POST, PUT, PATCH kiwa DELETE
↓
Router URL la ViewSet action sobat map karto
↓
ViewSet Required API operation execute karto
↓
Response Client la result milto

2. Types of ViewSets

DRF madhye commonly use honare ViewSet classes:

ViewSet Purpose
ViewSet Custom API actions define karne.
GenericViewSet GenericAPIView chi functionality provide karte.
ModelViewSet Complete CRUD operations provide karte.
ReadOnlyModelViewSet Fakt list ani retrieve operations provide karte.

3. ViewSet

ViewSet hi basic class aahe. Ya class madhye aapan list, create, retrieve, update ani delete sarkhya actions manually define karto.

Definition

ViewSet is a base class that allows developers to define custom actions for API endpoints.

Example

from rest_framework.viewsets import ViewSet
from rest_framework.response import Response

class StudentViewSet(ViewSet):

    def list(self, request):
        return Response({
            "message": "Student list"
        })

    def create(self, request):
        return Response({
            "message": "Student created"
        })

Important Points

  • list(): Multiple records fetch karte.
  • create(): New record create karte.
  • retrieve(): Single record fetch karte.
  • update(): Complete record update karte.
  • partial_update(): Specific fields update karte.
  • destroy(): Record delete karte.
Important: Basic ViewSet madhye he actions automatically implement hot nahit. Aplyala required actions swatah define karave lagtat.

4. GenericViewSet

GenericViewSet hi class GenericAPIView chi functionality provide karte.

Definition

GenericViewSet provides the functionality of GenericAPIView and can be combined with Mixins to build API operations.

Example

from rest_framework import mixins
from rest_framework.viewsets import GenericViewSet

class StudentViewSet(
    mixins.ListModelMixin,
    mixins.CreateModelMixin,
    GenericViewSet
):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer

Explanation

  • GenericViewSet: GenericAPIView chi functionality dete.
  • ListModelMixin: list() method provide karte.
  • CreateModelMixin: create() method provide karte.
  • queryset: Student records select karto.
  • serializer_class: StudentSerializer select karto.

Ya example madhye List ani Create operations available hotat. Itar operations sathi additional Mixins add karave lagtat.

5. ModelViewSet

ModelViewSet ha ViewSets madhil important class aahe. Ya class madhye complete CRUD operations already available astat.

Definition

ModelViewSet provides list, create, retrieve, update, partial_update and destroy actions for a model.

Example

from rest_framework.viewsets import ModelViewSet

class StudentViewSet(ModelViewSet):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer

Available Actions

Action HTTP Method Purpose
list GET All students fetch
create POST New student create
retrieve GET Single student fetch
update PUT Complete update
partial_update PATCH Partial update
destroy DELETE Student delete
Remember: ModelViewSet vaparlyavar pratyek action sathi separate method manually lihinyachi garaj naste.

6. ReadOnlyModelViewSet

ReadOnlyModelViewSet cha use fakt data read karanyasathi hoto. Ya madhye create, update ani delete operations available nastat.

Definition

ReadOnlyModelViewSet provides only list and retrieve actions to read data.

Example

from rest_framework.viewsets import ReadOnlyModelViewSet

class StudentReadOnlyViewSet(ReadOnlyModelViewSet):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer

Available Actions

  • list(): All records fetch karte.
  • retrieve(): Single record fetch karte.
Supported Methods 
GET /api/students/
GET /api/students/1/

7. What are Routers?

Routers cha use ViewSet sathi automatically URL patterns generate karanyasathi hoto.

Definition

Routers automatically generate URL patterns for registered ViewSets.

Types of Routers

Router Purpose
SimpleRouter Basic API URL patterns generate karto.
DefaultRouter API URLs sobat API root view pan provide karto.

Router Import

from rest_framework.routers import DefaultRouter

Register ViewSet

router = DefaultRouter()

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

Ithe students ha URL prefix aahe ani StudentViewSet ya prefix sobat register kela aahe.

8. How Router Maps URLs?

Router HTTP methods la ViewSet actions sobat automatically map karto.

HTTP Method URL ViewSet Action
GET /students/ list()
POST /students/ create()
GET /students/1/ retrieve()
PUT /students/1/ update()
PATCH /students/1/ partial_update()
DELETE /students/1/ destroy()
Important: Router la ViewSet register kelyanantar manually pratyek action sathi URL lihinyachi garaj naste.

9. Practical Student CRUD API using ModelViewSet

Ata aapan ModelViewSet ani DefaultRouter vaprun complete Student CRUD API create karuya.

Step 1 – Model

Topic 15 madhil Student model already asel tar toch use kara. 

# api/models.py

from django.db import models

class Student(models.Model):

    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)
    age = models.PositiveIntegerField()

    def __str__(self):
        return self.name

Step 2 – Serializer

# api/serializers.py

from rest_framework import serializers
from .models import Student

class StudentSerializer(serializers.ModelSerializer):

    class Meta:
        model = Student
        fields = '__all__'

Step 3 – ViewSet

File: api/views.py

from rest_framework.viewsets import ModelViewSet

from .models import Student
from .serializers import StudentSerializer


class StudentViewSet(ModelViewSet):

    queryset = Student.objects.all()
    serializer_class = StudentSerializer

Step 4 – Router and URLs

File: api/urls.py

from rest_framework.routers import DefaultRouter
from .views import StudentViewSet

router = DefaultRouter()

router.register(
    'students',
    StudentViewSet,
    basename='student'
)

urlpatterns = router.urls

Step 5 – Main URLs

File: config/urls.py

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('api/', include('api.urls')),
]
Important: Existing Student model ani serializer astil tar te punha create karu naka. Router use kartana tyach ViewSet sathi duplicate URL patterns add karu naka.

11. Generic Views vs ViewSets

Generic Views ViewSets
Each view class specific operations handle karte. Multiple operations ekach class madhye group hotat.
URL patterns manually define karave lagtat. Routers automatically URLs generate karu shaktat.
ListCreateAPIView example. ModelViewSet example.
Separate endpoints var jast control. Related CRUD operations organize karne sope.
