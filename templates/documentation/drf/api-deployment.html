DJANGO REST FRAMEWORK

34. API Deployment in DRF

Learn how to deploy a Django REST Framework API and make it available on the internet.

1. What is API Deployment?

API Deployment mhanje local computer var develop kelela API internet var available karne. Deployment nantar dusre users suddha API access karu shaktat.

Definition

API Deployment is the process of publishing an API to a server so that users can access it through the internet.

Example

Local API vs Live API

Local API:
http://127.0.0.1:8000/api/students/

Live API:
https://example-api.onrender.com/api/students/

Local API fakt tumchya computer var access karta yete. Live API internet connection aslelya users na access karta yete.

2. Development vs Production

Development environment coding ani testing sathi asto. Production environment actual users sathi asto.

Development Production
Local computer var run hoto. Internet var run hoto.
DEBUG = True asu shakto. DEBUG = False thevava.
SQLite use karu shakto. PostgreSQL sarkha production database use karu shakto.
Development server use hoto. Production WSGI server use hoto.

3. Production Settings

Production madhye Django settings secure ani properly configure karne mahatvache aahe.

Important Settings

  • SECRET_KEY – Django security key.
  • DEBUG – Error details users na show karayche ka te control karte.
  • ALLOWED_HOSTS – Allowed domain names define karte.
  • DATABASES – Database connection configure karte.
  • STATIC_ROOT – Collected static files chi directory.

Example – settings.py

import os

SECRET_KEY = os.environ["SECRET_KEY"]

DEBUG = os.environ.get("DEBUG", "False").lower() == "true"

ALLOWED_HOSTS = os.environ.get(
    "ALLOWED_HOSTS", ""
).split(",")
Important: Production madhye DEBUG=False theva. SECRET_KEY code madhye hardcode karu naka.

4. Environment Variables (.env)

Environment Variables cha use secret information ani configuration code pasun vegli thevanyasathi hoto.

Definition

Environment Variables are external configuration values used by an application without hardcoding them into the source code.

Example – .env

SECRET_KEY=your-secret-key
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost
DATABASE_URL=your-database-url

Read Environment Variables

Local development madhye python-dotenv package vapru shakto. 

pip install python-dotenv

settings.py

import os
from dotenv import load_dotenv

load_dotenv(BASE_DIR / ".env")

SECRET_KEY = os.environ["SECRET_KEY"]

DEBUG = os.getenv("DEBUG", "False").lower() == "true"

.gitignore

.env
venv/
__pycache__/
*.pyc
db.sqlite3

.env file GitHub var push karu naka. Deployment platform madhye environment variables manually configure kara.

5. DEBUG and ALLOWED_HOSTS

DEBUG

DEBUG setting development madhye detailed error information show karte. 

DEBUG = False

ALLOWED_HOSTS

ALLOWED_HOSTS madhye application access karu shaknare domain names define kele jatat. 

ALLOWED_HOSTS = [
    "example-api.onrender.com",
    "localhost",
    "127.0.0.1"
]

Actual deployment madhye tumcha live domain ALLOWED_HOSTS madhye add kara.

6. PostgreSQL Database

PostgreSQL ha relational database aahe. Production Django applications madhye PostgreSQL commonly use kela jato.

Install Packages

pip install dj-database-url psycopg2-binary

Configure Database

settings.py

import dj_database_url
import os

DATABASE_URL = os.getenv("DATABASE_URL")

if DATABASE_URL:
    DATABASES = {
        "default": dj_database_url.config(
            default=DATABASE_URL,
            conn_max_age=600,
            ssl_require=True
        )
    }
Note: DATABASE_URL madhye database connection details astat. Ti secret information aahe. Public GitHub repository madhye share karu naka.

7. Static and Media Files

Django project madhye static files ani media files vegveglya purpose sathi use hotat.

Static Files Media Files
CSS, JavaScript, logos. User uploaded images and documents.
Developer provide karto. Users upload karu shaktat.

Static Settings

settings.py

STATIC_URL = "static/"

STATIC_ROOT = BASE_DIR / "staticfiles"

MEDIA_URL = "/media/"

MEDIA_ROOT = BASE_DIR / "media"

WhiteNoise Installation

pip install whitenoise

WhiteNoise Middleware

MIDDLEWARE list madhye SecurityMiddleware nantar WhiteNoiseMiddleware add kara. 

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
    # Other middleware
]

Static Files Storage

STORAGES = {
    "staticfiles": {
        "BACKEND": (
            "whitenoise.storage.CompressedManifestStaticFilesStorage"
        ),
    },
}

Collect Static Files

python manage.py collectstatic --noinput
Important: WhiteNoise static files serve karanyasathi aahe. User-uploaded media files sathi production madhye persistent disk kiwa cloud storage configure kara.

8. Deploy Django API on Render

Render he cloud platform aahe. Tyavar Django application deploy karun live API URL milavu shakto.

Step 1 – Install Gunicorn

pip install gunicorn

Step 2 – Update requirements.txt

pip freeze > requirements.txt

Step 3 – Push Code to GitHub

git add .
git commit -m "Prepare API for deployment"
git push origin main

Step 4 – Create Render Web Service

  1. Render website open kara.
  2. GitHub account connect kara.
  3. New Web Service select kara.
  4. Tumchi Django repository select kara.
  5. Python runtime select kara.
  6. Build Command configure kara.
  7. Start Command configure kara.
  8. Environment Variables add kara.
  9. Deploy Web Service click kara.

Build Command

pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate

Start Command

gunicorn config.wsgi:application

Ya example madhye Django project package che nav config aahe. Tumchya project madhye package name vegle asel tar te vapra.

Step 5 – Environment Variables

Render dashboard madhye Environment section open karun required variables add kara. 

SECRET_KEY = your-production-secret-key

DEBUG = False

ALLOWED_HOSTS = your-service.onrender.com

DATABASE_URL = your-postgresql-database-url

Actual values tumchya Render service ani database nusar configure kara.

9. Test API After Deployment

Deployment successful zalyanantar live API endpoint test karne avashyak aahe.

Example

GET

https://your-service.onrender.com/api/students/

Check These Things

  • Live API URL open hoto ka?
  • GET request expected data return karte ka?
  • POST request record create karte ka?
  • Database connection working aahe ka?
  • Authentication properly work karte ka?
  • Static files properly load hotat ka?

10. Common Deployment Errors

Error Possible Solution
DisallowedHost ALLOWED_HOSTS madhye correct domain add kara.
ModuleNotFoundError Missing package requirements.txt madhye add kara.
Database Connection Error DATABASE_URL ani database settings check kara.
Static Files Not Found STATIC_ROOT ani collectstatic check kara.
Application Failed to Start Start command ani deployment logs check kara.
500 Internal Server Error Server logs madhil actual error check kara.

11. Important Points to Remember

  • Deployment mule API internet var available hote.
  • Production madhye DEBUG=False theva.
  • SECRET_KEY environment variable madhye theva.
  • ALLOWED_HOSTS madhye live domain add kara.
  • PostgreSQL production database mhanun use karu shakto.
  • Gunicorn production WSGI server mhanun use hoto.
  • WhiteNoise static files serve karu shakto.
  • collectstatic static files collect karte.
  • Media files sathi persistent storage configure kara.
  • Deployment nantar live API test kara.

13. Interview Questions

Q1. What is Deployment?

Deployment is the process of making an application available on a server for users.

Q2. Why is DEBUG=False used in production?

It prevents detailed technical error information from being exposed to users.

Q3. What are Environment Variables?

Environment Variables store application configuration separately from source code.

Q4. What is Gunicorn?

Gunicorn is a WSGI HTTP server used to run Python web applications in production.

Q5. What is WhiteNoise?

WhiteNoise helps Django serve static files in production.

Q6. What is collectstatic?

collectstatic collects static files from different locations into STATIC_ROOT.
